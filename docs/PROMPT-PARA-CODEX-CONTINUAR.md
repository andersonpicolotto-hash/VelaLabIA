# Prompt curto para continuar no Codex

Continue o projeto **VelaLab IA** com foco Deriv. Leia `README.md` e `docs/PLANO-E-CHECKPOINT.md` antes de alterar arquivos. O usuário aprovou desenvolver todas as 6 fases e deseja eventualmente execução automática de ordens em DEMO e REAL, mas **nenhuma ordem real está autorizada nesta sessão**. A seleção REAL existente é **somente consulta de saldo** no Android.

Não recomece o projeto. Reutilize o código do ZIP `VelaLabIA-Completo-Base.zip` e confirme 21 testes Python; corrija regressões. Priorize compilar APK Android pelo GitHub Actions (verificar log de erro real, não afirmar sucesso antes de aparecer `app-debug.apk`), testar no Galaxy S24 FE e validar leitura do feed público Deriv. Em seguida desenvolver compra e conciliação **apenas DEMO** com endpoints documentados. Nunca inserir senha ou token no repositório, nem enviar compra REAL sem confirmação posterior, testes, controles e reconciliação.

Na Fase 2 validar backtests contra dados cronológicos de qualidade e payout disponível, evitando otimização excessiva. Na Fase 3 construir avaliação walk-forward abrangente, modelo versionado com rollback e provas fora da amostra; IA não muda limites máximos de risco. Na Fase 4 usar o `compose.yaml` localmente antes de qualquer VPS; contratar infraestrutura somente com autorização de custos, HTTPS e segredo protegido. Fase 5 completar BrokerAdapter com gestão de posições e idempotência, reconexão segura e controles de exposição agregada; usar API oficial Deriv (REST OTP + WS) e jamais simular conexão real. Na Fase 6 validar 3–6 meses DEMO, auditoria, performance por estratégia/ativo/OTC/normal/1m/5m, estabilidade e falhas.

**A cada etapa:** (1) ler checkpoint, (2) pequena mudança, (3) testar, (4) registrar o que realmente foi testado, (5) salvar commit e checkpoint, (6) interromper em caso de crédito insuficiente. Não alterar código que funciona sem motivo; não confundir código experimental com produto validado.
